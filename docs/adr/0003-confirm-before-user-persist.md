# 用户修改先暂存、确认后才持久化

**Status**: accepted

用户对稿件的任何修改（改字 / 说话人 / 加行 / 删行 / 润色）先进入"待提交"暂存态，只有用户点「提交改动」（或定稿）后才以一条 ChangeSet 持久化。

**Why**: 一次用户修改会破坏相关行的 TTS 缓存、并作为一条消息追加进 AI 上下文——都是有代价的操作，需要确认门，避免误触和零散记账，也给整体撤销留了空间。Agent 用工具（add / edit）发起的修改走工具返回，不追加上下文，也不需要确认门。

**Consequences**: 编辑页出现暂存条（N 处改动待提交 · 撤销全部 / 提交改动）；定稿前自动提交待改动，保证脚本基于已确认持久化的状态。
