# 用户修改先暂存、确认后才持久化

**Status**: accepted（重构后重写依据：单层模型下用户改台词/改指令会触发该行素材重合成）

用户对脚本的任何修改（改台词 / 改指令 / 说话人 / 加行 / 删行 / 重排）先进入"待提交"暂存态，只有用户点「提交改动」后才以一条 ChangeSet 持久化。

**Why**: 用户修改是有代价的操作，需要确认门，避免误触和零散记账，也给整体撤销留了空间。代价来自两点：

1. 每次提交会作为一条紧凑 ChangeSet 消息追加进 AI 上下文（ADR-0002），零散提交会污染上下文；
2. **修改触发重合成成本**：单层模型下脚本行就是音频素材的源头（ADR-0001/0006）——用户改台词 / 改指令，该行素材下次合成时作废重生成。确认门让用户"一次改到位再确认"，避免每改一个字就触发一次重合成。

Agent 用工具（add / edit）发起的修改走工具返回，不追加上下文，也不需要确认门。

**Consequences**: 编辑页出现暂存条（N 处改动待提交 · 撤销全部 / 提交改动）；合成前自动提交待改动，保证合成基于已确认持久化的状态。改台词 / 改指令 → 该行音频素材作废，下次合成重生成（ADR-0006）；改停顿 / 改语速是后期参数，不触发素材重写（ADR-0004）。
