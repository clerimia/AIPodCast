# 用户修改先暂存、确认后才持久化

**Status**: accepted

用户对稿件的任何修改（改字 / 说话人 / 加行 / 删行 / 润色）先进入"待提交"暂存态，只有用户点「提交改动」（或定稿）后才以一条 ChangeSet 持久化。

**Why**: 用户修改是有代价的操作，需要确认门，避免误触和零散记账，也给整体撤销留了空间。代价来自两点：

1. 每次提交会作为一条紧凑 ChangeSet 消息追加进 AI 上下文（ADR-0002），零散提交会污染上下文；
2. 修改影响下一次定稿：重定稿产生全新的脚本行（冷缓存），整版重新合成才有新内容。

注意：用户修改**不直接破坏音频缓存**——缓存挂脚本行（ADR-0006），与稿件无关；受影响的是下一版脚本行的冷缓存。

Agent 用工具（add / edit）发起的修改走工具返回，不追加上下文，也不需要确认门。

**Consequences**: 编辑页出现暂存条（N 处改动待提交 · 撤销全部 / 提交改动）；定稿前自动提交待改动，保证脚本基于已确认持久化的状态。
