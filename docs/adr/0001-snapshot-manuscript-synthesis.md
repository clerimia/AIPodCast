# 合成只针对"脚本"（定稿生成的不可变快照），而不是活稿件

**Status**: accepted

合成（含重新合成）只读"脚本"——每次定稿把当前稿件的内容**物化成不可变快照**（script_lines = 拷贝的顺序 / 说话人 / 文本 + 默认 TTS 配置），而绝不读正在编辑的稿件。

**Why**: 编辑与合成因此完全解耦。合成是脚本行上的状态机（待合成 → 合成中 → 已合成），永远不会和用户正在编辑的稿件争同一份数据——无需锁、无需冻结稿件，定稿只是生成脚本的动作。换音色后对某版脚本"重新合成"即用新音色重做（音色不随内容冻结）。

**为什么是拷贝而不是引用（必须，不是冗余）**:

脚本行是定稿那一刻从稿件行**拷贝**（顺序 / 说话人 / 文本）而来的，且**不引用稿件行**（无血缘指针）。这是必须，不是冗余：

1. **稿件行会变、会删**（逻辑删除）：脚本行若引用稿件行，内容会随稿件漂移、随删行失效。
2. **确定性与可复现**：合成读自足快照，同一版脚本任何时候合成都得同一结果。
3. **独立演化**：稿件怎么改都不影响已定稿的脚本，两层的演化彻底解耦。
4. **自证存档**：脚本行本身就是"定稿那一刻内容的存档"，拷贝即证据，无需回溯稿件历史。

将来任何人试图把脚本行改成"引用稿件行"来省空间，都违背本 ADR。

**Consequences**: 脚本内容随定稿冻结（脚本行拷贝顺序 / 说话人 / 文本，各有独立 uuid）；音色不随内容冻结——脚本行只记 speaker_id，重新合成跟随当前说话人配置。脚本表按定稿顺序形成版本历史；一版定稿 = 一版脚本。
