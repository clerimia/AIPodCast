# 按页面拆成两个平级 AI 会话：写稿大师 + 调音大师，而不是单一主会话

**Status**: accepted

会话按页面职责拆成两个平级的独立上下文：编辑页的**写稿大师**（稿件工具 read/add/edit/retrieve）和脚本页的**调音大师**（tune + 读脚本）。不再有"单一主会话"，调音大师也不是任何一方的主会话子代理。

**Why**: 两个角色的工具面完全不同（写稿大师写稿件内容、调音大师改脚本行的 TTS 配置），工具不同意味着它们各自需要独立、隔离的上下文——调音大师根本套不进"子代理"的模型。按页面 = 按职责 = 按工具面，是最自洽的切法；交接点就是定稿生成的脚本（写稿层的产出、调音层的输入），互不进入对方上下文。

**Consequences**: 跨页对话记忆断裂——写稿大师讨论"为什么这么写"的语境不会传给调音大师，后者只能从脚本本身推断。这是有意的隔离：各自上下文小、缓存友好（ADR-0002），但用户要接受"调音大师不知道为什么这么写"。调音大师的会话还要**按脚本挂**：一版脚本一个会话线程（conversation ↔ script_id，UNIQUE），点开哪版脚本会话就跟到哪版、切换脚本即切换会话——保证每版脚本的 TTS 配置讨论彼此隔离，不会因为换脚本串台。Auditor 是唯一子代理，与两个大师平级，不归属任何一方。
