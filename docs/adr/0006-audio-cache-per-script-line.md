# 音频缓存挂脚本行，破坏缓存 = 特定行为重写音频

**Status**: accepted

音频缓存（tts_cache）以脚本行为外键（script_line_id UNIQUE，每脚本行 0..1 份单行音频），**与稿件无关**——稿件怎么改都够不到缓存。缓存键 = script_line_id，不做唯一内容 hash。

**Why**: 缓存真正的主战场是单脚本内的试听 → 调整 → 批量拼接循环：试听单行即合成并落缓存；批量合成逐行查缓存、命中复用、未命中补合成；改动的行单独重生成、其余命中。缓存跟随脚本行、由特定行为显式失效，比内容寻址更简单、更贴合这个循环。为此有意的取舍：**不做跨版本共享**——重定稿产生全新脚本行（冷缓存），整版重新合成；换来的是缓存与稿件彻底解耦、失效路径清晰可枚举。

**Consequences**:

- 破坏缓存 = 特定行为重写对应脚本行的音频：
  - 改语气 / 语速 / 情感 → 重写该行（单行、精准）
  - 强制重新生成 → 显式重写（绕过缓存 / 清条目后重生成）
  - 换音色 / 换 TTS 模型 → 批量重写所有受影响脚本行的缓存
  - 改停顿 → 只重拼接，不重写（停顿是拼接参数，ADR-0004）
- 试听 = 单行合成入口，与批量共用同一条流水线与同一份缓存；拼接产物（master）不缓存——它是便宜的，按脚本存 artifacts（0..1、重新合成替换）。
- 缓存行随脚本级联清理（script → script_lines → tts_cache ON DELETE CASCADE）。
- 稿件修改不触缓存（ADR-0003）；只影响下一次定稿的新脚本行（新行冷缓存）。
