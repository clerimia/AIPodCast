# 修改以 ChangeSet 追加进 AI 上下文，而非每次重读脚本

**Status**: accepted

写稿大师会话的上下文 = 稳定系统提示 + 节目元数据 + 按序追加的 ChangeSet + 近期对话。数据库是真相源，上下文是只追加、不改写的消息流。

**Why**: 只追加、前缀稳定，命中 LLM prompt 缓存；写稿 / 改稿 / 审核共享同一份脚本视图。代价是上下文可能短暂滞后于数据库，但单用户 + 行级原子修改，事件量小，可接受。

**Consequences**:

- 只有**用户发起的修改**会生成一条紧凑的 ChangeSet 消息追加进上下文，让 Agent 知道外界发生了什么。
- **Agent 用工具（add/edit）发起的修改不追加**——工具返回结果就是 Agent 所见，避免重复记账、浪费上下文。
- **双视图控制读成本**：上下文常驻的是紧凑增量（ChangeSet，只记 id + 操作类型，不带全文）；全量脚本只在需要时经 `read` 按行 / 范围读取，从不明文 dump 进主会话；读全脚本的审核在 Auditor 隔离上下文里做。
- 任何修改仍在同一个事务里落库（script_lines + change_sets）；绕过该管线的直接改库会让 Agent 视图失联。
